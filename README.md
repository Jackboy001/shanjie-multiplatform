# 善解（Windows）

讓注音輸入更符合你的習慣。善解結合上下文選字、中英混打與個人詞庫，提供接近微軟注音的操作方式，也保留善解原有的選字與預測功能。

## 特色功能

- **中文、英文與數字接著打**：提供「原鍵混打」與「上游判斷」兩種方式，減少手動切換中英。原鍵混打先顯示按鍵並提示注音，聲調完成後轉成中文，按 Enter 可保留原文。
- **選字會記住你的習慣**：支援上下文選字、語意校正、聊天／書面詞句偏好與個人選字學習；也可開啟模糊注音、鄰鍵容錯及中英文自動加空格。
- **保留熟悉的操作**：Windows 與善解兩套操作預設，可調整開候選、方向鍵、空白與 Enter 的行為；候選可展開為三欄，也能使用即時讀音預測與選字後聯想。
- **反白就能加詞**：在支援的程式反白漢字、連按兩下 Ctrl，即可在詞旁確認讀音並加入個人詞庫；支援可讀取反白內容的唯讀文字，也提供替代快捷鍵。
- **模型由你選**：內建一套完整模型，可在設定取得其他相容配套、查看評測備註，再下載並切換。切換不會自動清掉其他已下載模型。
- **外觀由你決定**：淺色、深色與跟隨 Windows 主題；強調色可跟隨系統或自訂，深色可使用純黑背景。善解動畫可獨立設為跟隨系統、強制開啟或關閉。
- **也能直接打注音文**：開啟「純注音輸出」，逐鍵輸入注音符號與聲調，不轉成漢字。
- **輸入內容留在本機**：詞庫、模型推論與學習都在電腦上處理；所有 App 共用登入時預載的核心，輸入內容不會上傳。

這是 [Jackboy001 的協作 fork](https://github.com/Jackboy001/shanjie-multiplatform)。正式專案、安裝檔與版本公告以 [tavricccc/shanjie-multiplatform](https://github.com/tavricccc/shanjie-multiplatform) 為準；原始碼版本與通道見 [RELEASE-CHANNEL.json](RELEASE-CHANNEL.json)，已發布版本見 [Releases](https://github.com/tavricccc/shanjie-multiplatform/releases)。版本歷程見 [Changelog](Changelog.md)，各版說明在 [docs/releases/](docs/releases/)。

## Windows 安裝

支援 **x64 Windows（含 32 位元 App）**，尚不支援 Windows on ARM。Windows 版使用原生 TSF 輸入法與 WinUI 3 設定程式；Linux IBus 版停在 0.12.1，已停止維護，`linux/` 未持續編譯或測試。

1. 從[正式版下載頁](https://github.com/tavricccc/shanjie-multiplatform/releases/latest)下載 `Shanjie-Windows-Setup.exe` 並執行。想試用新功能，可到[所有版本](https://github.com/tavricccc/shanjie-multiplatform/releases)選標示 **Pre-release** 的測試版；原始碼版本不代表安裝檔已發布。
2. 選擇標準注音或倚天注音（更新時預選目前的配置），按「安裝」並同意 UAC。之後要換鍵盤，重新執行安裝程式即可。
3. 登出再登入，在輸入法清單選「善解注音」。

安裝只把善解加到輸入法清單最後（沒有中文（台灣）時一併加入），不改動其他語言與輸入法。所有 App 共用一個登入時啟動的常駐核心。

善解預設在登入時與之後每天檢查新版（只查詢 GitHub，不傳送輸入內容），有新版時在螢幕右下角通知，不會自動下載；可在設定的「關於」關閉「自動檢查更新」。也可在「關於」按「檢查更新」，下載並核對後自動安裝並重新開啟設定；「更新通道」預設只看正式版，改成測試版才會列出較新的測試版；也可以直接執行新版安裝程式。個人詞庫、學習、設定與下載的模型都會沿用。已開啟的 App 要重新開啟才會用到新版；任何一步失敗都會嘗試完整回復。

## 設定

安裝完成畫面可直接開啟設定；之後在輸入法的中英模式按鈕按右鍵，或執行安裝目錄的 `settings.cmd`。修改後按「儲存」才套用，不需要管理員權限。

第一次開啟時可透過「快速設定」選擇打字方式，也能在「一般」重新開啟。升級者預設保留現有設定；若選用快速設定範本，會重新建立 profile，舊檔先備份成 `profile.ini.before-quick-setup.bak`。略過或關閉不會改寫設定，個人詞典與學習資料不受影響。

「鍵盤配置」可跟隨已安裝的標準／倚天配置，或選漢語拼音、臺灣拼音（通用拼音）；未安裝的注音配置不能選取。兩份操作範本的主要差異：

| 項目 | Windows 範本 | 善解範本 |
| --- | --- | --- |
| 開啟候選 | ↓（可改空白或兩者） | ↓／空白 |
| 候選範圍 | 游標右側 | 游標左側 |
| 移動候選 | ↑↓ 或 ←，Tab／→ 展開三欄（可改） | ←→ 或 ↑↓，Tab 關閉候選並交給 App |
| 選字 | 數字確認；Enter 確認並提交 | 數字／Enter 確認後繼續組字 |
| Enter 提交範圍 | 只提交游標前，固定詞不拆開 | 整句（可另開游標前提交） |
| 空白鍵 | 插入可編輯空格（可改操作候選） | 開候選、候選中換頁 |
| 單按 Shift | 切換中英 | 切換中英 |
| Caps Lock | 照打注音 | 暫時輸入英文 |
| 選字學習 | 開啟 | 開啟 |
| Shift＋空白／Ctrl＋標點 | 全半形／全形標點 | 關閉 |
| 即時讀音預測 | 關閉 | 開啟，Tab 進入、Shift＋Tab 退出 |
| 選字後聯想 | 關閉 | 關閉 |

候選預設直式，每頁最多 9 項，字級 14–32 DIP；展開時以三欄顯示更多候選。完整鍵位與每個設定見 [微軟注音對照與設定索引](docs/MICROSOFT-IME-DIFFS.md)。

開啟「記憶選字」後，數字鍵、Enter 或滑鼠確認候選就會建立暫存記憶，組字提交時保存；改選、刪字或取消會撤回尚未確認的記憶。「Enter 只提交游標前」也會保留完整詞組的選字記錄，例如將「風之谷」改成「楓之谷」，分段送出仍能記住整個詞，無須先按 End。連續分段累計超過 128 音節時，先保存已送出的部分，再開始下一段學習。

- **中英混打**：「中英混打與切換」頁三選一：關閉、原鍵混打或上游判斷，預設上游判斷（上游未支援的鍵盤配置下不生效）。原鍵混打模式下，未完成的輸入先顯示原始按鍵（如 `gj`），下方提示 `ㄕㄨ`，聲調完成後轉中文，Enter 保留原文；這個模式一定會開啟組字面板。上游判斷限標準注音：注音不可能是想打的字時整段變回按鍵當英文（馬上按 Esc 變回注音），Shift＋字母開始英文段。
- **組字面板**：「組字與提交」頁的選項，預設關閉，組字只顯示在 App 內，沒有候選時不顯示面板，與上游相同。開啟後在候選窗位置顯示整句組字，游標移進句子時標出游標所在的字，使用者可依需要開啟（游標在句尾時不標；原鍵混打標的是正在打的注音）。
- **純注音輸出**：「組字與提交」頁可切換，預設關閉。開啟後，標準／倚天注音逐鍵輸出符號與聲調，例如 `su3cl3` 得到「ㄋㄧˇㄏㄠˇ」，不自動轉成漢字或開啟候選、預測及聯想，也不加入選字學習。空白鍵輸入空格；方向鍵、刪除、Enter 提交與 Esc 沿用組字操作。切換時先提交現有組字；關閉後恢復原有輸入設定。拼音配置不啟用此模式，數字鍵盤仍直接輸入數字。
- **貢獻者**：「關於」頁列出貢獻者（原作者 Nanako0129 置頂並標示，其餘依 GitHub 提交數排序，不顯示次數），滑鼠移入姓名可看貢獻摘要，也可開啟個人頁面與提交紀錄。頭像先連線載入，失敗時使用隨程式附上的頭像；統計更新方式見[貢獻者資料](docs/CONTRIBUTORS.md)。
- **上游功能**：資訊與 AI 詞包、模糊輸入、語意校正強度、中英文之間自動加空格、依 App 自動切換聊天／書面都可在設定中開關。

### 外觀與動畫

「外觀」頁的設定同時供設定程式、候選窗與加詞浮層使用：

- **主題**：跟隨 Windows、淺色或深色。
- **強調色**：善解預設藍、Windows 系統色，或以色盤／六位 HEX 自訂。選取文字會依底色採用黑或白，維持可讀性。
- **深色純黑**：將深色背景改為不透明的 `#000000`，保留控制項與邊框；淺色與高對比不套用此選項。
- **動畫**：跟隨系統、強制開啟或關閉。強制開啟只影響善解，不會修改 Windows 的動畫設定。

設定草稿可在設定視窗預覽，儲存後才套用到輸入法；高對比模式的配色優先使用系統色。

### 個人詞庫與反白加詞

在「預測、詞庫與學習」可一次貼上多行詞庫，每行填「注音 字詞」，音節以 `-` 分隔，例如：

```text
ㄕㄢˋ-ㄐㄧㄝˇ 善解
```

第三欄可指定非正數分數，省略時為 `-0.01`。儲存後先提交現有組字，再載入詞庫。

也可反白 **1–32 個漢字**後雙按 Ctrl，在詞旁的浮層確認或修改讀音，再加入個人詞庫。加入前會比對內建詞庫、個人詞庫與目前模型。可編輯欄位與支援讀取反白內容的唯讀文字均可使用；沒有輸入讀音時會提供可能的讀音，破音字請先確認。「快捷鍵與符號鍵」可調整 Ctrl 的左右側、間隔或替代快捷鍵，避免與其他工具衝突。

加詞需要來源程式提供可讀取的反白文字；密碼欄位不支援，Excel 儲存格反白取詞目前不列入支援範圍。

### 模型下載與選擇

內建會意 **SJ-SR-8-15M** 語意校正模型與上游 v0.6.1 的其餘完整配套（含口語模型）。其他配套可在設定的「取得其他模型」查看線上清單、最後更新時間與評測備註；通過格式、相依模型與核心相容性檢查的配套才可選用，評測差異以備註說明。

下載時會核對大小與 SHA-256，建立並驗證本機快取。**下載並選取後，仍須按主視窗「儲存」才套用。** 已下載配置可離線使用，切換到其他模型不會自動移除它；模型資料夾可從設定旁的按鈕開啟，重新掃描後只有通過驗證的完整配套會列入選單，不能只放任意單一模型檔。

配置名稱會列出搭配的模型，名稱很接近也可能使用不同版本或附加模型；長名稱會換行，展開清單可捲動並標示目前選項。既有合法下載配套保留原來源收據，新下載改由[上游鏡像](https://github.com/tavricccc/shanjie-upstream-backup)提供；線上來源暫時無法取得時，仍可使用本機有效配套。

### 資料保存與分享設定

個人資料位於 `%LOCALAPPDATA%\Shanjie\`：

| 內容 | 位置 |
| --- | --- |
| 完整設定 | `profile.ini` |
| 個人詞庫 | 由 profile 的 `[input] dictionary` 指定的檔案 |
| 選字學習 | `learning.tsv` |
| 已下載模型與附件快取 | `Models\` |
| 匯入的操作預設 | `presets\` |

一般更新會沿用這些資料。**「匯出操作預設」只分享按鍵、選字與預測等操作習慣，不是完整設定或資料備份**；不包含個人詞庫、學習、模型、詞包、鍵盤配置與外觀等個人項目。需要完整保留時，請另備份資料夾與詞庫實際路徑指向的檔案。

直接修改 `profile.ini` 後，按設定頁的「重新啟動輸入法」或重新啟用善解才會讀取；這個按鈕不會終止 App，也換不掉 App 已載入的舊版 DLL。

## 解除安裝

從「已安裝的應用程式」移除，或在設定的「關於與相容性」頁按「解除安裝善解…」。仍被 App 載入的檔案在重新登入或重新開機後刪除。個人資料可以選：

- **保留個人詞庫與選字學習**（預設）：移除程式與設定，詞庫與學習供重新安裝使用。
- **一併移除個人詞庫、學習與設定**。

選擇移除時個人資料會直接刪除，無法復原。命令列可用安裝目錄的 `uninstall.cmd`，或 `tools/shanjie-manager.exe --elevate uninstall --keep-user-data`／`--delete-user-data`。

## 疑難排解

| 紀錄 | 位置 |
| --- | --- |
| 設定啟動失敗的完整例外 | `%LOCALAPPDATA%\Shanjie\Logs\ui-startup-*.log` |
| 輸入法與加詞輔助程式的有限錯誤／生命週期紀錄 | `%TEMP%\shanjie-tsf.log` |
| 安裝錯誤原因 | `%ProgramFiles%\Shanjie\.installer-recovery\<識別碼>\error.txt` |
| 安裝階段與回復結果 | 同目錄 `events.jsonl` |
| 檔案清單校驗 | 同目錄 `validation.json` |
| 早期安裝失敗 | `%LOCALAPPDATA%\Shanjie\installer-logs\<識別碼>\` |

錯誤對話框會附上可取得的紀錄位置。一般執行紀錄只包含有限的階段、版本及錯誤碼，不記錄輸入內容或反白字詞；設定啟動日誌會包含程序路徑與完整例外，分享前可先檢查。DLL 目前沒有數位簽章。

## 開發

需要 PowerShell 7、Git、Rust MSVC、Visual Studio Build Tools（MSVC、Windows SDK resource compiler）與 .NET 10 SDK。

```powershell
git clone --recurse-submodules https://github.com/Jackboy001/shanjie-multiplatform.git
cd shanjie-multiplatform
git submodule update --init         # 已有 checkout 時補齊固定版本的上游
pwsh -File scripts/package.ps1      # 建置並打包成 dist/Shanjie-Windows-Setup.exe
pwsh -File scripts/verify-changed.ps1 -DryRun  # 查看本輪變更需要的驗證
pwsh -File scripts/verify-changed.ps1          # 執行對應驗證
pwsh -File scripts/verify.ps1       # 完整核心與 Windows 回歸；合併／發布前依維護規則執行
```

上游子模組固定在 `UPSTREAM.json` 指定的 commit；不要直接改成任意最新版本。建置所需模型會依 `MODEL-SOURCES.json` 下載並核對 SHA-256，需要網路；私人詞典與學習資料不進原始碼或安裝包。

正式 repo 的發布透過升版 PR：合入 `main` 且 `windows/Cargo.toml` 的版本號變更後，GitHub Actions 先建置、測試及校驗所有指定平台，再補齊同來源草稿的附件並公開 Release。手動執行 workflow 預設為 `verify`，不發布；已公開的 Release 不會被重跑覆寫。fork 的 Actions 與正式發布各自獨立，更新本 fork 不代表正式安裝檔已發布。

`build.ps1` 的 `-UseExistingCore` 略過 prepare，`-SkipSettings` 重用已發佈的設定程式；`package.ps1 -UseExistingBuild` 只重新整理與打包現有 `dist/`。
